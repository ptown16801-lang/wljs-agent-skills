# I1 - stray `General::stop` cell on built documentation pages (fixed)

Repo: local vendored MarkdownToNotebook, commit `4d1e139`
(`~/.local/share/wolfram-agent-skills/markdown-to-notebook/4d1e13918c464b89a72ee47d97f49d5d9efd52b5/`).
Patch: `patches/I1-build-stray-general-stop.diff` (two files). Backups: `<file>.orig-2026-10-22`.

## Change

1. `examples/Paclet/DocPageExamples/build.wls`, `buildDoc`: each page is converted once. The
   `"Association"` result already holds the finished notebook (`info["Notebook"]`), so it is written with
   `exportDeterministicNB` (the writer `MarkdownToNotebook[src, file]` uses itself). The second
   `MarkdownToNotebook[src, out]` call, which ran every example a second time, is gone. `$MessageList` is
   Block-scoped per page (`Block[{..., $MessageList = {}}, ...]`).
2. `MarkdownToNotebook.wl`, `captureCellRun` (about line 1068): `$MessageList = {}` is added to the
   per-cell `Block`. In a notebook each input cell is its own evaluation, so the General::stop count
   starts again in every cell. Without this, all cells share one `$MessageList`, and a message issued
   once per cell becomes a General::stop cell on the third such cell.

Why part 2 is needed: with part 1 alone, the ragged page came out clean, but `Lorem.nb` got a
General::stop cell instead. In the offline build, every Lorem example cell issues
`ServiceExecute::isrv` (that failure is W2), and one conversion has four such cells. The old double
conversion happened to hide this. In a fresh kernel, a single conversion of `Lorem.md` gives 4 isrv cells
plus 1 General::stop cell. With the per-cell scope it gives 4 isrv cells and no stop cell (scratch
experiment `exp-lorem*.wls`).

## Limits / open points

- `exportDeterministicNB` is an internal top-level helper of `MarkdownToNotebook.wl`, not a documented
  API. It is reachable because the converter is plain top-level code, but a rename upstream would break
  `build.wls`.
- `examples/build.wls` (lines 85-87) uses the same double-conversion pattern. I did not change it (out of
  scope). The per-cell scope in the converter removes this symptom there too.
- The Lorem page still shows four `ServiceExecute::isrv` failures in an offline build. That is W2, not
  this bug.
- `MANIFEST.sha256` in the vendored copy no longer matches the changed files. I left it as is so that
  the change stays visible.
- Run environment: the prescribed `bwrap --unshare-net ...` command with `$AllowInternet = False`. For
  builds and test runs I added two isolation flags: `--bind` of scratch copies of `~/.Wolfram/FrontEnd` and
  `~/.Wolfram/Logs`. I also pointed the converter's example cache at a scratch `PersistenceLocation`
  (`$cacheLocation`, protected before `Get`), so builds wrote no FE preferences or cache objects to
  `~/.Wolfram`. Kernel start-up still updates `~/.Wolfram/Paclets/Configuration` as usual. One early
  probe wrote `~/.Wolfram/Objects/Persistence/mtnbOverlayProbe`, and I deleted it right away.
