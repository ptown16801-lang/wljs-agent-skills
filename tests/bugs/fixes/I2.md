# I2 - DocPageExamples paclet: three functional defects (fixed)

Patch: `patches/I2-docpageexamples-maze-defects.diff`. It covers
`DocPageExamples/Kernel/DocPageExamples.wl`, `docs/MazeParse-ragged.md`, `docs/DocPageExamples.md` and
`ResourceDefinition.md`, all under `examples/Paclet/DocPageExamples/`. Backups: `<file>.orig-2026-10-22`.

## Changes

1. **MazeParse ragged rows.** The behaviour is kept: every row is fitted to the header (first) line's
   width, with shorter lines padded with `#` and longer lines truncated. What changes is the report:
   - The message now names the first line whose length differs from the header row. Before, it named
     the shortest line, which was the header itself when a later line was longer.
   - The message says whether that line is shorter or longer, gives both lengths, and states the rule:
     `Line 2 is longer than the header row (7 instead of 5 characters); shorter lines are padded with
     walls and longer lines are truncated to the header width.`
   - The usage string says the same.
   - The doc page `docs/MazeParse-ragged.md` now covers longer lines. Its bullet says "first ragged
     line" instead of "shortest line", and a new Scope example shows a truncated line. The guide's
     one-line summary is updated.
2. **MazeGenerate[{1, 1}].** A 1 x 1 maze has one cell, so the start and goal cannot be distinct. The
   call is rejected: `MazeGenerate::small` is issued and the call stays unevaluated (a condition on the
   definition). `{1, 2}` and `{2, 1}` still work with S and G distinct. The usage string says "at least
   two cells". `ResourceDefinition.md` changes "of any size" to "of any size from two cells up".
   `mazegen` already clips sizes to 2..60, so `docs/mazegen.md` needed no change.
3. **`.maze` extension.**
   - `ImportExport`RegisterImport`/`RegisterExport` register only the converters. Their `"Extensions"`
     option is not seen by `FileFormat`, which is what `Import`/`Export` use to pick a format; I tested
     this with a scratch format. `PacletInfo` has no extension type for file formats.
   - So the kernel file now registers MAZE with `FileFormatDump`AddFormat` after `RegisterExport`. The
     spec is `FileNamePatterns -> {"*.maze"}`, MIME `TEXT/X-MAZE`, `FormatTest -> None` (matched by file
     name only).
   - The call is guarded so it runs once per session (no duplicate on reload) and inside
     `Quiet@Check`, so loading never fails.
   - `Import["file.maze"]` and `Export["file.maze", expr]`, both stated on the Format page, now work.

## Limits / open points

- `FileFormatDump`AddFormat`, `FileFormatDump`$FILEFORMATS` and the spec keys are undocumented
  Import/Export internals, checked only in Wolfram 15.0. On another version the registration may do
  nothing (quietly). `Import[f, "MAZE"]` always works.
- I kept truncation of long lines rather than padding every row to the longest line. That is the smaller
  change, and it keeps the page's "header row" model. Data beyond the header width is dropped, and the
  message now says so.
- `MazeGenerate[{1,1}]` now returns unevaluated where it used to return a grid. Callers that relied on
  getting a (broken) grid will see the message instead.
- `MANIFEST.sha256` no longer matches the changed files.
