# W4 fix: schematic lines end on guessed, not real, library connector positions (Oct 22, 2026)

Toolkit: `~/.local/share/wolfram-system-modeler-ai-toolkit/991a800.../annotate-modelica-graphics/`. Changed:
`Schematic/routing.py`, `layout.py`, `inject.py`, `main.py`, `SKILL.md` (backups `*.orig-2026-10-22`); new
`Schematic/libpins.py`. Patch: `patches/W4-wsm-toolkit-pins.diff` (`cd <toolkit root>; patch -p0 < ...`; checked
that it rebuilds all six files from the backups). Evidence: `fixes/scratch-W4/` (`before/`, `after/`, `bulk/`,
`check_vs_sm.py`/`.txt`, `render.wls`, PNGs). Every run was under `bwrap --unshare-net`. The kernel renders used a
fresh `wolframscript` with `$AllowInternet = False`. Pure Python standard library; nothing under `/usr/local` was
written.

## What changed
- **`libpins.py` (new).** For a library component it opens the class's `.mo` source in the System Modeler install
  (read only). The install is found with the toolkit's own `scripts/wsm_run.py`: `find_install`, `find_msl` (MSL
  version from the model's `uses(...)`, else the newest 4.x) and `resolve_library` for the other installed
  libraries. It walks the package directories, `package.mo` files and nested classes. Then it finds the
  connector's declaration, following `extends` (relative names, `import`s, short class definitions and `IconMap`
  extents). It reads `Placement(iconTransformation(...))`, or `transformation(...)` when there is no
  `iconTransformation`, and takes the centre of the placement box through its origin, extent (including flips) and
  rotation. That point is normalised from the class's Icon `coordinateSystem` (own, else inherited, else ±100) to
  the ±100 frame.
  - Type names in the user's model are resolved through its `import`s and its `within` scope, so relative names
    inside library packages also work.
  - Only depth-0 `annotation`/`Placement`/`Icon` elements are used. Vendor entries such as
    `ModelEditor = Icon(list(...))` are skipped. So are the "classes" the shared parser reports inside
    modifications (`redeclare package Medium = Medium`).
  - Files, classes, coordinate systems, imports and pins are cached per process.
  - `place()` implements the Modelica placement transform. It is also used for the instance end of the route.
- **`routing.py`.** `_port_offset` tries, in order: the model's own generated icon, then `libpins`, then the old
  name heuristic (`_lib_edge`) only as a fallback. Every fallback adds a warning to the layout, naming
  `instance.port`, the type, the reason and the guessed edge.
  - Endpoints are computed with `place()` (instance extent ±10, origin, rotation) and written exactly. A pin that
    is not on the integer grid now gives up to 2 decimals instead of being rounded.
  - An element of a connector array (`u[1]`) of an in-file icon uses that connector's generated pin.
- **`layout.py`.** The two-port orientation step uses the real library pins (dominant axis), with
  `local_extends`/`scope` passed through.
- **`inject.py`.** Calls `libpins.configure(text)`, passes in-file `extends` lists and class scopes, and collects
  the warnings into each class summary.
- **`main.py`.** Prints `WARNING: ...` lines under the class and a count line. Example of the fallback output when
  no install is found:
  `WARNING: prismatic.axis (Modelica.Mechanics.MultiBody.Joints.Prismatic): connector position not read from
  library source (System Modeler install not found); guessed the left-edge midpoint (-100,0) from the port name -
  check this line`.
- **`SKILL.md`.** The "Layout is heuristic" note now says that library pins come from the library source, and that
  guesses are reported as warnings.

   (PlanarMechanics, BioChem, ModelPlug).

3. **Regression runs** (`--annotate --force --write`, old vs new). ElectricCircuit and ElectricCircuit2 give

4. **Fallback check.** With `WSM_HOME=/nonexistent` the Submarine lines are identical to the original output and
   10 `WARNING:` lines are printed.

## Remaining limits / open points
- **Routing still ignores which way a pin faces.** Lines can run through their own component's icon when the other
  end lies behind the pin (Submarine: `world.frame_b -> prismatic.frame_a` crosses World; `flange -> axis` crosses
  the prismatic body and passes over its disabled `support` pin; BlockCircuit: `gain1.y -> add3.u1`). This is a
  layout/routing problem separate from W4 (before the fix, other lines crossed icons), and needs outward stubs or
  side-aware routing.
- Hand-written instance Placements are not used for routing; the computed layout positions are used, as before.
- Not covered: connectors whose placement uses parameter expressions, connectors that a `redeclare` moves,
  inherited nested classes in name lookup, `encapsulated`, and encrypted `.moe` libraries. Each of these falls back
  with a warning.
- The shared parser cannot parse a few MSL files (`Units.mo`, some `Media`, `Math/Nonlinear.mo`). None of them
  defines placed components; a component there would fall back with a warning.
- The connector point is taken as the box centre, which assumes a symmetric connector coordinate system (true in
  MSL).
- Observed once and not investigated: one `wolframscript` render printed unrelated association text
  (`screenplay+fan: ...`) instead of the script's output. A rerun was normal.
